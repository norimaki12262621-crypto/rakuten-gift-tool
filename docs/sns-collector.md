# SNS商品画像 自動収集

## 利用手順

1. ランキング画面の新しいリンクから収集画面を開く。
2. 商品名、任意のブランド、1行に1色の色番号・色名・濃度を入力する。最大6色。在庫切れを含めるか、1検索の商品数も選べる。
3. 「商品検索・画像収集を開始」で複数ショップを検索。色番号による検索と共通商品検索を併用する。必要なら次ページも収集する。
4. 元画像、商品名、価格、レビュー、商品URL、解像度、OCR表記、評価根拠、HTTP結果を比較する。
5. 自動照合できない色は手動確認画面で画像と商品ページを確認し、OCR誤読を訂正して採用する。別色の商品名・濃度違いの商品レコードは対象色へ転用できない。
6. Instagram 4:5 / TikTok 9:16を選ぶ。採用画像と利用条件を確認してZIP保存する。

候補と選択はメモリ内に保持する。再読込で消えるため、必要な画像と取得結果はZIPへ保存する。

## 自動検索・収集

- 楽天API `/api/sns-search` をサーバーで実行。ショップを指定せず、商品名・ブランド・色番号で横断検索する。
- 色番号がある場合、ブランド＋商品カテゴリ＋色番号でも表記ゆれを検索する。共通商品ページも検索し、同じ商品・画像は重複排除する。
- APIが返す画像URLだけを候補にする。大サイズ取得を選んだ場合も同じAPI画像の `_ex` サイズ指定だけを変更し、画像パス・ファイル名は推測しない。APIの返却URLと実際の取得URLを両方記録する。
- `/api/rakuten-image` は楽天サムネイルドメインの既定パスだけを取得。リダイレクト、別ホスト、非画像形式を拒否し、15秒/3MBに制限する。
- 実画像の幅・高さ、HTTP状態、配信元エラー、SHA-256を記録する。元バイト列は変更せず保持する。
- 1回の収集は最大120画像。1検索あたりの商品数は4/8/15/30、各検索は10ページまで。処理中は進捗と中止ボタンを表示する。対象色が多い場合はOCRに数分かかることがある。

## 本体優先の補助評価

画像を内部の分析用Canvasで縮小し、有色領域の大きさ、矩形の埋まり方、OCR文字数、元画像の解像度を用いてスコアを出す。領域が大きい画像を優先し、箱・全面バナー・文字が多い画像の可能性にはペナルティを付ける。

これは本体・箱を確実に認識するモデルではない。白い商品、小さな色番号、複数商品の構図、ロゴを完全には判別できない。画像が確認済み・高い補助スコア・本体らしい形の条件を満たす場合にのみ、自動候補を予備選定する。利用者は元画像と採用内容を確認し、変更・解除できる。

分析用の縮小・OCR処理は保存画像に適用しない。ショップロゴの除去、画像の切り抜き、商品本体の描き直しは実施しない。

## 3状態での照合

- **確定**：商品名・ブランド・指定色番号・色名・濃度と画像内表記を照合できたもの、または人が元画像と商品ページを照合して確定したもの。
- **要確認**：色番号が読めない、複数色の共通画像、色名が確認できない、OCR信頼度不足など。自動確定・ZIP採用をしない。
- **不一致**：商品名が別色・濃度違い、または信頼できるOCR表記が別色・濃度違い。別色へ自動流用しない。

取得失敗は上記の色照合状態と別に表示する。01と101、A03の30％とB03の70％を区別する。商品タイトルの「全24色」などをB03の色番号と誤認しない。低信頼度OCRノイズは不一致ではなく要確認に残す。

OCRはTesseract.jsの日本語＋英語モデルをブラウザ内で実行する。低解像度・装飾文字・小さい番号は読めないことがある。初期化失敗・35秒の認識タイムアウト時は画像収集を続け、色は手動確認に残す。中止時は通信とOCRワーカーを止める。

## ZIPとmanifest

未選択・要確認・不一致・画像取得失敗の対象が残る場合、ZIP出力を無効化する。出力内容：

- `images/`：採用した各画像の取得元バイト列。JPEG/PNG/WebPの形式を保持する。
- `manifest.json`：商品名、ブランド、色番号、色名、濃度、ファイル名、商品コード、ショップ、商品URL、アフィリエイトURL、API掲載参考価格、在庫、レビュー、元画像URL、取得URL、解像度、SHA-256、HTTP結果、照合根拠、OCR表記、手動訂正、確認者、補助評価、投稿先の比率。
- `collection-report.json`：採用しなかったものも含め、各候補の取得結果・エラー・色状態・解像度を記録。
- `README.txt`：ChatGPT側で元画像を使用し、商品をAIで描き直さず、未確認色へ流用しないための受け渡し説明。

共通ページの価格は色別の実売価格と断定しない。コードがない/複数色のページは共有ページ参考価格として記録する。

## 認証・利用条件・共有

APIキーは環境変数からサーバーで使用する。クライアントHTMLの認証IDを除去し、楽天レスポンスの認証値・`rafcid`を除去する。ZIPにキーを含めない。既存ランキングも同じサーバー処理を使い、デフォルトの価格範囲や商品コード検索を維持する。

API取得はSNS転載許諾ではない。外部公開の利用条件を自動で許諾済みとは扱わない。利用規約・アフィリエイトガイドライン・取得元の条件を利用者が確認する欄を設け、manifestはその操作を `user-reviewed` と記録する。権利者からの許諾取得を保証する値ではない。

この環境から楽天公式規約ホストへのアクセスはプロキシCONNECTの403で拒否されたため、最新規約本文の自動取得・法的適否の確認は未完了。画面から公式リンクを開いて確認する。サーバーへの画像アップロード、公開ストレージ保存、ChatGPT向けの外部共有URL生成は実装しない。受け渡しはローカルZIPとし、公開・デプロイは行っていない。

## 実施した検証

- 起動正常、リポジトリ読取正常、楽天API HTTP 200。
- 実API検索から実画像10件を取得し、日本語＋英語OCRがローカルで完走した。例：fwee B02では7商品/10画像を取得。小さい色番号が読めない画像は要確認に残った（確定したとは報告しない）。
- 色番号拡張検索が、purecoの在庫切れB02を含む複数ショップの実レコードを取得。
- 実API画像のバイト列を使用したUI検証で、手動訂正・採用・変更、取得エラー、3状態、4:5/9:16、ZIPの元バイト列とSHA-256一致、manifestの色・ファイル・URL対応、APIキー不在を確認。
- リポジトリ内の決定的なブラウザ回帰テストは技術用1px PNGと固定OCR結果を使用。実API/実OCRの統合確認とは区別する。ページ送り・重複排除・中止・失敗表示・出力ガード・390px幅も確認。
- 既存ランキングは実APIから60件取得・5商品表示。既存TikTok手動画像選択ゲートも保持。JavaScriptエラーなし。
- `npm test`、`CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`、`npm run build`を実行して通過。

実通信・UI確認のスクリーンショットは実行環境の `/workspace/rakuten-gift-tool-local/sns-collector/` に保存している。
